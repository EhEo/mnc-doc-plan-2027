## 0. 요약 (Executive Summary)

### 0-1. 문제 인식

모덕보 표준 견적은 **단일 서버 1대 구성** 으로 다음 항목이 모두 부재합니다:

| 누락 항목 | 위험 영향 |
|-----------|-----------|
| 백업/Standby 서버 | 서버 장애 시 **MES 전체 다운** → 419대 설비 실시간 데이터 수집 중단 |
| DB 이중화·복제 | 데이터 손실 시 **공정 이력·BOM·QC 데이터** 영구 소실 가능 |
| 핵심 3계층 스위치 이중화 | 단일 스위치 장애 시 **전체 공장 통신 두절** |
| 정전·UPS 정책 | 베트남 현지 정전 빈발 → **데이터 손상·하드웨어 고장** 위험 |
| DR(재해 복구) 사이트 | 화재·수해·랜섬웨어 대응 불가 |
| RPO/RTO 명시 | 복구 목표가 불명확하여 **계약 SLA 협상 불가** |

기존 모덕보 견적은 980대 CNC 기준이므로, M&C 실규모(419대)에 맞춰 **하드웨어·라이선스·구축 비용 모두 재견적**을 받아야 합니다.

## B-2. 자동화 설비 50대 — 통신 프로토콜 검증

자동화 설비는 단순 CNC와 달리 **PLC·로봇·센서·비전 시스템** 이 혼재합니다. 각 설비의 통신 프로토콜에 따라 IPC·게이트웨이 구성이 달라집니다.

| 설비 종류 | 일반 프로토콜 | 모덕보 지원 여부 (질의 필요) |
|-----------|---------------|------------------------------|
| 6축 로봇 (FANUC/KUKA/ABB) | EtherNet/IP, Profinet, Modbus TCP | (질의) |
| PLC (Siemens/Mitsubishi/Omron) | Profinet, Modbus, MELSECNet, OPC-UA | (질의) |
| 비전 시스템 (Cognex/Keyence) | RS-232/Ethernet, GigE Vision | (질의) |
| RFID 리더기 | TCP/IP, Serial | (질의) |
| CMM (Zeiss/Mitutoyo/Hexagon) | I++ DME, OPC-UA, FTP | (질의) |
| **CNC 컨트롤러 (FANUC/Siemens/Mazak/Brother)** | **FOCAS, MTConnect, OPC-UA, MELSEC** | (질의) |

> **추가 질의 필요**: 모덕보가 위 프로토콜을 어디까지 직접 지원하는지, 어디부터는 **별도 게이트웨이/미들웨어**가 필요한지 명확히 받아야 합니다.

## B-3. 금형자동화 14대 PC — 연동 방식 정의

14대 PC는 **이미 자동화 라인(천진 迈凯 자동화)에 포함된 운영 PC**로 추정됩니다. 모덕보 MES와의 연동 방식은 다음 3가지 중 결정 필요:

| 옵션 | 설명 | 장단점 |
|------|------|--------|
| **A. PC가 클라이언트** | 14대 PC가 모덕보 MES 클라이언트 앱을 설치하여 직접 접근 | 단순, 단 라이선스 14개 추가 |
| **B. PC ↔ IPC 중계** | PC 데이터를 IPC가 수집하여 MES로 전송 | 라이선스 절감, 단 미들웨어 개발 필요 |
| **C. API 인터페이스** | PC가 REST/MQTT로 MES API 호출 | 가장 유연, 단 모덕보 API 사양 확인 필요 |

> **권고**: 옵션 C를 우선 검토하되 모덕보 API 공개 범위 확인 후 결정.

## 6. 결론

특히 **M&C 실제 규모(CNC 355 + 자동화 50 + PC 14 = 419대)** 가 모덕보 표준 견적(980대)의 약 **43% 수준**이므로, IPC 수량은 6대 → 4대로 줄일 수 있으나 **서버 이중화·UPS·NAS·DR 비용 추가**로 인한 총 투자 변동을 모덕보 측에 정확한 수정 견적을 받아야 합니다.

5월 6일 삼성 미팅에서는 본 자료의 **이중화 아키텍처와 베트남 현지 대응 항목**을 "고객사 안정성·보안 보증" 메시지로 활용 가능하며, 미팅 후 5/13까지 모덕보 답변 수령을 목표로 즉시 송부할 것을 권고합니다.
